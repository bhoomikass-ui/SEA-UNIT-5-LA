## 1. Introduction

Open-source software is software whose source code is freely available
for users to view, modify and improve.

GitHub is a platform used by developers to share code and collaborate on
software projects.

## 2. Problem Analysis

The Library Management System does not have proper documentation
explaining how users can issue and return books.

Because of this, users may find it difficult to understand the book
issuing and returning process. The project needs clear and simple
documentation.

## 3. Proposed Solution

A student can improve the project by creating or updating a Markdown
documentation file.

The file should explain: - **Issue Book:** Students can select an
available book and request it. - **Return Book:** Students can return
the borrowed book to the library. - **Book Availability:** Users can
check whether a book is available.

The student can contribute this file to the faculty's GitHub project
using the fork and Pull Request workflow.

## 4. Importance of Contributing to Open-Source Projects

1.  Improves software quality.
2.  Helps developers learn new skills.
3.  Encourages teamwork.
4.  Helps find and fix errors.
5.  Improves project documentation.

## 5. GitHub Contribution Procedure

### 5.1 Steps to Fork a Repository

1.  Open the faculty GitHub repository.
2.  Click the **Fork** button.
3.  Select your GitHub account as the owner.
4.  Keep the repository name unchanged.
5.  Click **Create fork**.
6.  A copy of the repository will be created in your account.

### 5.2 Creating or Modifying a Documentation File

1.  Open the forked repository.
2.  Open the `contributions` folder.
3.  Click **Add file → Create new file**.
4.  Enter the required filename: `NB25CSE131-Mokshagna.md`.
5.  Add the documentation explaining how to issue and return books.
6.  Save the changes.

### 5.3 Committing Changes and Submitting a Pull Request

1.  Click **Commit changes**.
2.  Enter a suitable commit message.
3.  Commit the file to the `main` branch of your fork.
4.  Return to your forked repository.
5.  Click **Contribute → Open pull request**.
6.  Check that the faculty repository is selected as the base repository
    and `main` is the base branch.
7.  Click **Create pull request**.
8.  Copy the Pull Request (PR) URL and submit it to the faculty as
    evidence.

## 6. Benefits and Challenges

### Benefits of Collaborative Software Development

1.  Better code and documentation quality.
2.  Faster development.
3.  Knowledge sharing.
4.  Easy identification and fixing of errors.
5.  Improved teamwork.

### Challenges

1.  Merge conflicts may occur when multiple people edit the same file.
2.  Contributions need to be checked and reviewed before merging.

## 8. Conclusion

Open-source software engineering encourages collaboration and knowledge
sharing. By creating clear documentation and submitting it through
GitHub, students can improve the Library Management System. The fork,
commit and Pull Request process makes it easier to contribute to a
shared project and gain practical experience.
